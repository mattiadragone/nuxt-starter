# Nuxt 3 + Vue 3 + Supabase (DB + Auth) + GSAP + Vercel Starter

A minimal, production-ready starter that uses **Nuxt 3 (Vue 3)** with **GSAP** animations, **Supabase** (database + auth), and **Vercel** deployment.  
Includes a protected route example, SSR database rendering, and a couple of API endpoints.

> ✅ Yes: this project runs **Vue 3** (via **Nuxt 3**).

## Environment Variables
Create a `.env` from `.env.example`:

```
NUXT_PUBLIC_SUPABASE_URL=your-project-url
NUXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key   # server-only
```

- `NUXT_PUBLIC_*` keys are **public** (exposed to client) — keep only anon, never secrets.
- `SUPABASE_SERVICE_ROLE_KEY` is **private**: used **only on server** (API routes) to read CMS-like content.

## Supabase Setup

### 1) Create Tables (SQL)
In SQL editor (Supabase), run:

```sql
-- Public demo table (client read)
create table if not exists public.demo_items (
  id bigint generated by default as identity primary key,
  name text
);

-- CMS-like table (server read with service role; can be public if you add RLS policies)
create extension if not exists pgcrypto; -- ensures gen_random_uuid on some stacks
create table if not exists public.cms_blocks (
  id uuid primary key default gen_random_uuid(),
  slug text unique,
  content text,
  published boolean default true
);
```

### 2) Row Level Security (RLS)
Enable RLS on both tables (Supabase UI → Table → RLS → Enable). Then add a simple policy for **public reads** on `cms_blocks` if you want the anon client to read published content directly (optional; by default the server endpoint uses the service role key to fetch content).

Example read-only policy for published content:

```sql
alter table public.cms_blocks enable row level security;

create policy "Public can read published content"
on public.cms_blocks
for select
to anon
using (published = true);
```

> ⚠️ Keep the **service role key** on the server only. The `/api/content` endpoint already uses it server-side.

### 3) Auth (Magic Link)
- In Supabase Dashboard → Authentication → Providers → **Email**: enable **Magic Link**.
- Set `emailRedirectTo` to your site origin (we pass `window.location.origin` in the code).  
- You can add OAuth providers later (Google, GitHub, etc.).

## 🧩 Extended Features (Added in This Build)

### 🔐 Auth (Email + Password)
- Login via **email + password**, replacing Magic Link.
- Users are managed directly in **Supabase Auth (`auth.users`)**, without a separate `profiles` table.
- Middleware `/protected` checks for valid Supabase sessions.
- To test locally:
  1. Go to **Supabase → Auth → Users → Add user**
  2. Add email + password, enable **Auto-confirm user**
  3. Login from `/login`

### 🧠 Dynamic CMS Architecture
A new centralized CMS system replaces separate API files for each component.

#### ✅ `server/api/cms.get.ts`
- Accepts query `?slugs=footer-note,home-hero`
- Uses server-only service role key (safe)
- Returns `{ ok, items, bySlug }` with caching via HTTP headers (`s-maxage` and `stale-while-revalidate`)

#### ✅ `server/utils/supabase.ts`
- Exports a helper that initializes a Supabase client using the **service role key**.

#### ✅ `composables/useCms.ts`
- Universal composable for fetching CMS content dynamically (SSR + client)
- Supports arrays of slugs and automatic caching with `useAsyncData`

#### ✅ `components/CmsBlock.vue`
- Flexible CMS-driven component:
  ```vue
  <CmsBlock slug="footer-note" as="footer" class="text-sm" />
  ```
- Handles loading, errors, and fallback messages gracefully.

#### ✅ Integration Example

### 🧩 Auth Middleware
```ts
export default defineNuxtRouteMiddleware(async (to) => {
  if (!to.path.startsWith('/protected')) return
  const { $supabase } = useNuxtApp()
  const { data } = await $supabase.auth.getSession()
  if (!data?.session) return navigateTo('/login')
})
```

## Deploy to Vercel
1. Push this project to GitHub (or GitLab/Bitbucket).
2. In Vercel, **New Project** → import the repo.
3. Framework preset: **Nuxt** (auto-detected).
4. Add the same env vars from `.env` to the Vercel Project Settings:
   - `NUXT_PUBLIC_SUPABASE_URL`
   - `NUXT_PUBLIC_SUPABASE_ANON_KEY`
   - `SUPABASE_SERVICE_ROLE_KEY`
5. Deploy. No extra config is needed (Nitro preset = `vercel`).

## Troubleshooting
- **Auth not working?** Check email provider config in Supabase and your redirect domain.
- **Client DB read fails?** Ensure RLS allows it (or use server endpoint).
- **`/api/content` error about config?** Make sure `SUPABASE_SERVICE_ROLE_KEY` is set in env.
- **Tailwind not applied?** Confirm the module is installed and `assets/tailwind.css` is imported by Nuxt (Nuxt auto-imports via module).
